# Промышленная мастерская

Первая ячейка связывает теорию с диагностикой перекладки деталей: конвейер → вакуумный захват робота → поддон 2 × 2.

- `#workshop`: лаборатория и пять сценариев.
- `#workshop-lab`: свободное изменение геометрии, задержек, вакуума и сигналов.
- `#workshop-case/WS-01` … `WS-05`: поиск причины по исходному прогону и измерениям, исправление, повторный прогон.

## Поведение

Лаборатория позволяет менять TCP X, начало поддона, шаг раскладки, скорость ленты, возраст координаты, потерю предельного вакуума, учёт времени и вход подтверждения. Прогноз пользователя сохраняется как текст для самопроверки. После изменения настроек результат прошлого прогона сбрасывается с экрана.

Схема показывает манипулятор, захват, ленту, датчик и четыре места на поддоне. Запуск, пауза и переход по одному этапу управляют воспроизведением. В режиме уменьшенного движения полный результат показывается без анимации. При выходе из раздела таймер завершается; незавершённая анимация не засчитывает прогон.

В диагностике параметры неисправности скрыты из панели. После исходного прогона доступны контроль TCP, разметка поддона, вакуумная кривая, монитор DI/DO и измерение времени/координат. Эти записи относятся к исходному состоянию и сохраняются для анализа после исправления. Новая конфигурация проверяется отдельным прогоном.

| Сценарий | Исходная неисправность | Необходимые наблюдения |
| --- | --- | --- |
| WS-01 | TCP X = +24 мм вместо 0 | Контроль TCP и отсутствие вакуума при промахе |
| WS-02 | Начало поддона смещено на +28 мм | Две метки поддона и исправный TCP |
| WS-03 | Потеря 55% предельного вакуума | Кривая давления и физическое состояние DI2 |
| WS-04 | Программа ждёт резервный DI3 | Вакуум набран, DI2 = 1, DI3 = 0 |
| WS-05 | Не учтены 120 мс при 200 мм/с | Временная шкала координат и исправный TCP |

Успех требует исходного прогона, выбранной верной причины, необходимых измерений и успешного нового прогона после всех изменений. Само нажатие исправления не даёт результата. Любое дополнительное изменение требует перепроверки. Подсказка или разбор отмечают помощь. Произвольный текст не оценивается автоматически.

## Математическая модель и границы

Все численные значения ниже — авторские константы учебного стенда, не параметры конкретного оборудования. Единицы: мм, с, кПа.

Лента движется равномерно. При моменте захвата `t = 0.8`:

```
x_actual = 120 + v × t
x_measured = x_actual − v × delay_ms / 1000
x_requested = x_measured + (tracking ? v × delay_ms / 1000 : 0)
x_tool = x_requested − tcpX
```

Реальный TCP X принят равным нулю, ориентация инструмента фиксирована и совпадает с базой. Поэтому ошибочная положительная настройка TCP даёт отрицательную ошибку реального положения. Контакт допустим при модуле ошибки не более 8 мм.

После включения DO1 при контакте давление относительно атмосферы изменяется по модели первого порядка:

```
p(t) = −60 × (1 − loss_percent / 100) × (1 − exp(−t / 0.35))
```

Без контакта давление равно нулю. Через 1 с проверяется реле DI2: `p ≤ −40 кПа`. Параметр потери уменьшает предельное разрежение и не является расходом утечки. При потере 55% предел составляет −27 кПа; дополнительное ожидание не позволит достигнуть −40 кПа. DI3 всегда 0. Движение к поддону разрешено только при подтверждении на выбранном входе. Исправление назначения входа сохраняет это требование.

Для столбца `c` (0 или 1), строки `r` (0 или 1):

```
x_target = 650 + c × 100
y_target = 105 + r × 100
x_placed = 650 + palletX + c × pitch − tcpX
```

Укладка успешна при отклонении каждого места не более 8 мм. Общий сдвиг и ошибка шага имеют разные признаки. Ошибка укладки не останавливает программную последовательность: её обнаруживает проверка результата.

Графика — схема вида сверху с двухзвенной проекцией манипулятора (звенья 290 и 260 условных единиц), а не цифровой двойник конкретной роборуки. Вертикальные перемещения, силы удержания, масса груза, динамика приводов и столкновения не рассчитываются. Время анимации иллюстрирует этапы, а журнал указывает времена модели первой детали.

## Хранение и упаковка

Модульные файлы `workshop-data.js`, `workshop-core.js`, `workshop-scene.js`, `workshop-ui.js` включены в Pages, Android-пакет и разрешённый список WebView. Дополнительных зависимостей, запросов к серверу и разрешений Android нет.

Ключ `robototehnika-bileti-ru:workshop:v1` отделён от тестов, расчётов и прежней практики. Сохраняются лабораторные параметры, прогноз, измерения, гипотеза, исправления, завершённые прогоны и заметки. Размер входного сохранения ограничен 70 000 символами, каждого свободного текста — 2000, изменений сценария — 20. Восстановление проверяет типы, диапазоны и известные ID; рассчитанный результат заново выводится из параметров. Пользовательский текст экранируется, ввод не исполняется. В обращение об ошибке входят только публичное условие, ID и ссылка на сценарий.

## Проверки

- `node --test tests/workshop.test.mjs`: независимые координаты и давление, причинность всех исправлений, признаки неисправностей, зависимость ошибки от времени/скорости, правила зачёта, повреждённые сохранения, достижимость схемы и автономная упаковка.
- `node scripts/check-workshop-ui.cjs` после сборки и установки Playwright: мобильный и настольный сценарии, все пять диагнозов, неверное исправление, необходимость повторного запуска, сохранение и экранирование заметок, приватность обращения, Android Back, пауза и выход с анимации.
- Прежние тесты и проверка банка запускаются вместе с новыми. Банк из 472 вопросов не меняется.
